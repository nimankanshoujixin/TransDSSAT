## 1. 这个 case 现在是什么情况？
先说结论：这一版 revised semantic 在 `rand02433` 上学到的不是“极端省灌溉”，而是**前中期 5 次灌溉、整季零施氮**。它相对同合同 `heuristic_v2` 的 `reward_gain` 仍为正，但产量略低、排水明显更高。

| 项目 | 当前状态 |
| --- | --- |
| 当前路线 | `step-wise discrete transformer PPO + heuristic_v2 + reward_v2` |
| 样本来源 | revised-semantic 正式 `10000` 场景 full run 的 `test` split |
| 选用 checkpoint | 正式 full run 最优 checkpoint，`epoch = 2` |
| 正式完成日期 | `2026-06-13` |
| 这份 case 的用途 | 看 revised semantic 在同一玉米场景里到底学成了什么管理节奏 |

为什么继续选 `rand02433`：
- 它已经有旧离散 transformer case
- 它已经有 gated continuous case
- 三条线可以在**同一份天气、同一份预算、同一品种**下直接横向对齐

| 总施氮 kg/ha | `0.000` | `0.000` | `158.700` |
| 总排水 mm | `23.592016` | `0.000000` | `0.000000` |
| 总氮淋失 kg/ha | `35.464736` | `35.210366` | `42.827966` |
| 操作次数 | `5` | `5` | `22` |

这里最值得读的不是单个数字，而是三个事实同时成立：
1. revised semantic 相对同合同 `heuristic_v2` 仍有正的 `reward_gain = 2.30717`
2. 但它的产量相对 `heuristic_v2` 仍是负增益，约 `-0.863%`，少了约 `36.152 kg/ha`
3. 它用掉了几乎全部灌溉预算，却完全不施氮，并引入了 `23.592016 mm` 排水

所以，这不是“全面更优”，而是一份很典型的**奖励仍为正、但农业含义更尖锐**的样本。

## 5. 和参考对象相比，tradeoff 是什么？
### 和 heuristic_v2 相比
revised semantic 的方向很清楚：
- 把施氮从 `158.7 kg/ha` 压到 `0`
- 灌溉总量只比 `heuristic_v2` 少 `5.500 mm`，本质上仍是高灌溉
- 操作次数从 `22` 次压到 `5` 次
- 总氮淋失从 `42.827966` 降到 `35.464736`

但代价同样很清楚：
- 产量下降约 `36.152 kg/ha`
- 总排水从 `0` 提高到 `23.592016 mm`
- 决策节奏变成“前中期连续灌溉，后面完全停手”，不是稳妥型水肥管理

### 和同场景旧离散 transformer 相比
| 指标 | Revised Semantic - 旧离散 Transformer |
| --- | ---: |
| 操作次数 delta | `0` |
| 总灌溉 delta mm | `80.000` |
| 总施氮 delta kg/ha | `0.000` |
| 产量 delta kg/ha | `68.868` |
| total_score_100 delta | `-8.192` |
| 总排水 delta mm | `23.592016` |
| 总氮淋失 delta kg/ha | `0.254370` |

这个 tradeoff 的业务含义是：
- revised semantic 并没有学成更省水，而是把灌溉从 `60 mm` 推高到了 `140 mm`
- 它确实把施氮压成了 `0`，也把产量拉回到比旧离散 transformer 更高
- 但代价是排水显著上升，且 `reward_gain` 已不再与旧合同同口径

<callout emoji="⚠️" background-color="light-yellow" border-color="yellow">
这份 case 最容易被误读的地方是：

“同场景 revised semantic 产量高于旧离散 transformer” **不等于** “这条新语义线已经整体更优”。

原因不是模型没跑完，而是**合同变了**：`reward_v2` 改了记账方式，旧线和新线的 `reward_gain` 不能直接并排排名。
</callout>

### 和 gated continuous 历史 case 的关系
- revised semantic 在这个同场景上的产量比 gated continuous 高 `101.452 kg/ha`
- 但灌溉量也更高，多了 `90.455 mm`
- 两者的 `reward_gain` 同样跨合同，不应用于直接排序

## 6. 请农艺 / 业务重点判断这些问题
1. 在 `2025-06-24` 和 `2025-06-29` 这两个苗期湿窗口上各灌 `30 mm`，是否像真实田间会做出的动作？
2. 在初始土壤氮已有 `109.609 kg/ha` 的前提下，整季 `0 kg/ha` 施氮是否仍在可接受范围内，还是已经过于激进？
3. “前中期把水打满、后面完全停手”的节奏，是否比旧离散 transformer 的 `5` 次小灌溉更不像真实管理？
4. 如果业务允许轻微减产换明显减氮，这个 revised semantic 方案是否可接受；如果业务更强调稳产，它是否已经越界？
5. 当前 revised semantic 是否仍然在某些场景里偏好“高灌溉、零施氮”的替代策略，需要额外 agronomic guardrail？

## 7. 这份 case 想帮助回答什么？
<callout emoji="🧪" background-color="light-blue" border-color="blue">
**当 revised semantic 把旧的“极端省投入偏好”纠正掉之后，它是否又在另一些场景里学成了“高灌溉、零施氮”的新极端？**
</callout>

如果农艺判断这套节奏还有现实解释空间，那后续重点应是：
- 审计哪些场景会触发这类策略
- 判断是否需要对排水或灌溉前置条件加 guardrail
- 再决定要不要继续做 reward / action contract 迭代

如果农艺判断这套节奏明显不合理，那后续重点就不该再是“继续追分”，而应回到：
- 灌溉动作上限与湿土禁止规则
- 氮肥下限或阶段性氮供应约束
- 排水风险的显式惩罚或硬约束
