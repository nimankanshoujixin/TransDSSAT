这次新合作方案，不是简单让我们“换一个数据集继续做原来的水肥优化”，而是把任务升级成：
连续农事窗口预测与决策引擎。
短期天气预报 每日巡田 无人机观测 窗口级建议 连续更新
我们当前更像：研究型水肥策略系统
对方希望的是：可落地的农事窗口预测产品引擎

一句话定位我们负责的部分

决策引擎
  • 我们负责：模型、决策、baseline、评测
  • 不直接负责：产品销售、APP 运营、数字农艺师体系
  • 和我们最接近的模块是：
    “管理分区与差异化处方生成模型”
  • 叶龄 / 物候期预测与我们相关，但更像上游输入模块，而不是我们单独要完整产品化的一整块。
核心信息：任务边界变了，我们需要先明确“我们负责哪一层”。

当前模型与对方需求的主要差异

维度 我们当前系统 对方希望的系统
输入 天气、土壤、作物、播期、水氮预算 天气预报 + 巡田观测 + 无人机 + 操作记录 + 分区标签

研究对象 冬小麦—夏玉米水肥优化 舒兰稻花香2号农事窗口预测
标签 / 目标 产量、成本、预算匹配 产量 + 风险 + 时机 + 可执行性

结论 1

当前系统不能直接平移过去，需要重新定义状态、动作和评测目标。

结论 2

这次变化不是“小改模型”，而是任务定义从“水肥优化”升级成“农事窗口预测与决策”。
核心信息：差异不是一个点，而是输入、输出、时序、作物对象、目标函数都变了。
Gap overview
第一类难点：状态、动作、reward 都要重构
03 / 07
难点 1

状态输入变复杂

  • 要加入叶龄、茎蘖数、水层、病虫害、无人机指标
  • 不再只是仿真场景输入
初步方案
先定义统一输入 schema；第一阶段只纳入最小必要字段，其他作为增强模块分批接入。
难点 2

动作不再只是水肥量

  • 后续要输出窗口建议
  • 包括晒田、穗肥、化调、防病、收获
初步方案
把动作拆成两层：上层是窗口触发，下层是具体操作强度；先做高价值窗口的 MVP。
难点 3

reward 体系必须升级

  • 现在主要看产量、成本、预算
  • 后面还要看风险和窗口时机
初步方案
把 reward 拆成多目标组件：产量、成本、风险、时机匹配、收获风险，先做可配置权重框架。
核心信息：不是调一下参数就行，而是状态、动作、reward 三件套都要升级。
Core model changes
第二类难点：上游依赖、作物切换、评测规则都不再简单
04 / 07
难点 4

上游模型与我们耦合

  • 叶龄、物候期、病虫害、水层等不是我们现在主线模型直接给出的
初步方案
把这些变量先定义成外部状态接口，支持“实测输入 / 合作方模型输出 / 近似估计”三种来源。
难点 5

作物系统切换

  • 从冬小麦—夏玉米，切到舒兰稻花香2号
  • 不是换文件，是换作物模板
初步方案
把作物知识模板化：`crop_template + variety_template + region_template`，保留旧模板，新增水稻模板。
难点 6

窗口级评测更难

  • 早 2 天或晚 1 天到底算不算错，不像产量那样天然有答案
初步方案
把评测拆成命中率、提前量、后果影响三类，先做“弱标签 + 专家规则 + 仿真结果”的混合评测。
核心信息：真正难的不只是模型本身，还有上游变量、作物模板和评测标准。
Dependency and evaluation challenges
第三类难点：我们要训练模型，就必须解决“数据从哪里来、结果谁来评”
05 / 07
新增核心难点
  • 如果最终要训练的是：
    农事窗口预测模型 / 连续决策模型 / DT + RL
  • 那就必须有大量训练样本。
  • 但真实田间样本少、慢、贵，而且标签不完整。
  • 更麻烦的是：即使模型生成了一个建议，我们还需要知道这套建议最终会带来什么结果。
当前 DSSAT 很适合评估水肥策略，但未必天然覆盖：
晒田窗口、化调窗口、防病窗口、收获窗口的好坏。

小规模严谨验证
  • 把“结果评估器”独立成系统组件，而不是隐含在模型里。
  • 先做双层数据生成体系：
    大规模近似训练数据 + 小规模高质量验证数据
  • 窗口类任务先用规则、历史记录和风险模型构造弱标签。
核心信息：没有大规模仿真数据和稳定评估器，后续再先进的模型也训练不起来。

希望老师支持我们明确的几件事
07 / 07

需要老师支持的关键点

  • 明确任务边界：
    我们负责决策引擎，而不是整套数字农业产品
  • 明确上游变量责任：
    叶龄、物候期、病虫害、水层、分区标签由谁提供
  • 明确目标函数优先级：
    产量、倒伏风险、病害风险、品质、收获风险哪个更重要
  • 明确数据可获得性：
    巡田数据、无人机数据、操作记录是否能标准化持续提供

我们当前的立场

我们不是在回避问题。
我们已经把任务切换后会遇到的关键技术难点拆清楚了，也给出了第一版解决路径。

现在最需要的是：
老师帮助我们明确边界、优先级和可用数据支持，便于我们按层次推进实现。
核心信息：我们已经从“问题识别”走到“可执行分阶段方案”，现在需要边界和资源支持。
