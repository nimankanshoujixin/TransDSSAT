## 1. 这个 case 现在是什么情况

先说结论：这次我继续沿用之前已经写过的 `rand02433` 玉米测试场景，原因不是偷懒，而是它能让连续动作线和之前的 MLP / 离散 transformer case 在**同一份天气、同一份预算、同一个作物品种条件**下直接对齐。

这份 case 对应的是：

| 项目 | 当前状态 |
| --- | --- |
| 当前路线 | `step-wise gated continuous-action + transformer` |
| 样本来源 | 正式 `10000` 场景 full run 的 `test` split |
| 选用 checkpoint | 正式 full run 最优 checkpoint，`epoch = 18` |
| 当前 line 总体状态 | 已完成正式 GPU 闭环，但总体仍未超过离散 transformer 权威基线 |
| 这份 case 的用途 | 看连续动作策略在单场景里到底学成了什么操作节奏 |

为什么它值得单独拎出来看：

- 它和之前的离散 transformer case 是**同一个场景**
- 连续动作版在这个场景里学到的不是“五次小灌溉”，而是**一次 49.545 mm 的早期单次灌溉**
- 这个策略在该单场景上的 `reward_gain` 反而**略高于**离散 transformer，但产量更低、排水更多

也就是说，这是一份很典型的“**局部更优但整体不一定更优**”样本。

## 3. 模型到底做了什么

<callout emoji="📌">
这版 `gated continuous` 在这个场景里最醒目的行为不是“把动作做得更细”，而是把整季操作**压缩成了一次早期大水脉冲**：

- 全季只有 `1` 次非零操作
- 这 `1` 次操作是 `2025-06-29 (day 5)` 的 `49.545 mm` 灌溉
- 全季 `0 kg/ha` 施氮
- 之后整个 season 都停手
</callout>

### 三方动作概览

| 指标 | Gated Continuous | 离散 Transformer | heuristic |
| --- | ---: | ---: | ---: |
| 非零操作次数 | `1` | `5` | `22` |
| 灌溉次数 | `1` | `5` | `22` |
| 施氮次数 | `0` | `0` | `11` |
| joint 次数 | `0` | `0` | `11` |
| 总灌溉 mm | `49.545` | `60.0` | `127.26` |
| 总施氮 kg/ha | `0.0` | `0.0` | `71.945` |

### 连续动作版唯一一次非零操作

| 日期 | day_index | 生育期 | 灌溉 mm | 施氮 kg/ha | 当日降雨 mm | 当次后剩余灌溉预算 |
| --- | ---: | --- | ---: | ---: | ---: | ---: |
| `2025-06-29` | `5` | emergence | `49.545` | `0.0` | `10.32` | `95.955` |

这张表说明了一个非常具体的农业问题：

- 它不是在持续补小水
- 也不是在高温高耗水窗口再出手
- 而是在**苗期偏湿窗口**一次性打入接近 `50 mm` 的水，然后后面再也不管

| 阶段 | Gated Continuous 事件数 | Gated Continuous 灌溉 mm | Gated Continuous 施氮 kg/ha | 离散 Transformer 事件数 | 离散 Transformer 灌溉 mm | heuristic 事件数 |

如果用一句话概括三方差异：

- `heuristic` 是全年持续小步管理
- 离散 transformer 是前期 `5` 次稀疏小灌溉
- `gated continuous` 则进一步走到“一次大水，后面全停”

## 4. 带来了什么结果

### 三方结果对比

| 指标 | Gated Continuous | 离散 Transformer | heuristic |
| --- | ---: | ---: | ---: |
| 产量 kg/ha | `4051.281` | `4083.865` | `4166.462` |
| reward | `14.35198` | `13.5616` | `5.2346` |
| reward_gain vs heuristic | `9.11738` | `8.327` | `0` |
| total_score_100 | `59.779` | `60.765` | `-` |
| 总灌溉 mm | `49.545` | `60.0` | `127.26` |
| 总施氮 kg/ha | `0.0` | `0.0` | `71.945` |
| 总排水 mm | `9.986093` | `0.0` | `0.0` |
| 总氮淋失 kg/ha | `35.313668` | `35.210366` | `38.663726` |
| 操作次数 | `1` | `5` | `22` |

这里最值得读的不是某一个单独数字，而是三个事实同时成立：

1. 这次 `gated continuous` 的单场景 `reward_gain` 确实比离散 transformer 更高，提升约 `+0.79038`
2. 但它的产量更低，较离散 transformer 少了约 `32.584 kg/ha`
3. 它引入了额外排水，且总分 `total_score_100` 反而略低了约 `0.986`

所以，这不是“全面更优”，而是一个很典型的**局部奖励更优、业务含义更尖锐**的 case。

## 5. 和参考对象相比，tradeoff 是什么

### 和 heuristic 相比

`gated continuous` 的方向很清楚：

- 操作从 `22` 次压到 `1` 次
- 灌溉从 `127.26 mm` 压到 `49.545 mm`
- 施氮从 `71.945 kg/ha` 压到 `0`
- reward gain 明显更高

但代价也很清楚：

- 产量下降约 `-2.764%`
- 单次大灌溉带来了 `9.986093 mm` 的排水

换句话说，它不是在“稳妥地优化”，而是在做一种**极简、早期一次性出手**的投入压缩策略。

### 和同场景离散 transformer 相比

这个对比更重要，因为离散 transformer 才是当前权威 AI 基线。

| 指标 | Gated Continuous - 离散 Transformer |
| --- | ---: |
| 操作次数 delta | `-4` |
| 总灌溉 delta mm | `-10.455` |
| 总施氮 delta kg/ha | `0.0` |
| 产量 delta kg/ha | `-32.584` |
| reward delta | `+0.79038` |
| reward_gain delta | `+0.79038` |
| total_score_100 delta | `-0.986` |
| 总排水 delta mm | `+9.986093` |
| 总氮淋失 delta kg/ha | `+0.103302` |

这个 tradeoff 在业务上真正意味着：

- 连续动作版确实学到了比离散动作更“狠”的稀疏化
- 它用一次 `49.545 mm` 的单次灌溉，替代了离散 transformer 的 `5` 次小灌溉
- 这种策略在当前 reward 合同下拿到了更高 reward
- 但它并没有把这个局部 reward 优势转化成更好的综合表现，反而带来了更低产量和更多排水

<callout emoji="⚠️">
这份 case 最容易被误读的地方是：

“单场景里 `reward_gain` 更高” **不等于** “整条连续动作线已经更优”。

正式总报告已经说明，`gated continuous` 在 `10000` 场景正式 full run 上总体仍然**没有超过**离散 transformer 权威基线。  
这份 case 的价值是解释它**局部到底学成了什么样子**，不是推翻整体结论。
</callout>

## 6. 请农艺 / 业务重点判断这些问题

1. 在 `day 5` 这种本来就有 `10.32 mm` 当日降雨、且前后窗口持续有雨的情况下，一次性灌 `49.545 mm` 是否像真实田间管理会做出的动作。
2. 在初始土壤氮 `109.609 kg/ha` 的前提下，整季 `0 kg/ha` 施氮是否仍在可接受范围内，还是已经过于激进。
3. “苗期一次大水，后面全停”的节奏，是否比离散 transformer 那种 `5` 次小灌溉更不符合农艺直觉。
4. 如果业务允许轻微减产换明显降投入，这种极简策略是否可接受；如果业务更强调稳产，这个方案是否已经越界。
5. 当前 reward 合同是否在某些场景里偏好“早打一笔大水然后停手”这类策略，从而把局部 reward 推高，却没有同步保证综合合理性。

## 7. 这份 case 想帮助回答什么

这份文档真正想帮助回答的不是“连续动作做没做出来”，因为那件事已经做出来了。  
它真正想帮助回答的是：

<callout emoji="🧭">
**当连续动作线在单场景里学到“一次大水、全季停手”这种模式时，我们认为它是在学更细的农业策略，还是在学更极端的 reward loophole？**
</callout>

如果农艺判断这种动作节奏仍有现实解释空间，那么后续连续动作线就值得继续优化约束和奖励，而不是直接判死。  
如果农艺判断这种节奏明显不合理，那么后续重点就不该再是“继续追分”，而应该回到：

- gate / amount 参数化
- 动作投影规则
- reward guardrail
- 产量与排水约束表达

## 附录 C. 后续如果要继续写连续动作 case，建议默认复用什么口径

1. 优先选已经有离散 baseline case 的同场景样本，避免换天气、换预算、换地块导致解释断层。
2. 先说整条 line 的正式状态，再说单 case 现象，避免把单场景局部现象误写成整线结论。
3. 必须同时给出 `heuristic` 和当前权威 AI baseline 的对照。
4. 必须把“动作节奏像不像真实管理”单独拎出来，而不只展示 reward。
5. 连续动作 case 里，优先强调：
   - 单次动作量是否出现明显非离散化特征
   - gate 是否学成“停手”，还是学成“永远微量非零”
   - 单场景局部优势是否只是用更激进 tradeoff 换来的
